## 一、这个项目要做什么

一个最小但完整的工业上位机：**串口采集 → Modbus 解析 → 实时曲线 → 阈值报警 → 数据落库**。

| 项 | 内容 |
|---|---|
| 一句话定位 | 手写 Modbus RTU 主站，把设备寄存器变成会动的曲线和能查的历史数据 |
| 技术栈 | Qt 5.15 / Qt 6（Widgets + SerialPort + Sql）+ `QPainter` 自绘 + SQLite + CMake |
| 关键设计 | **不引 `libmodbus`，帧自己拼、CRC 自己算**——手写才有得讲，这是这个项目唯一的面试价值来源 |
| 不做什么 | Modbus TCP 多从站、报表打印、OPC UA、主题换肤、多设备管理 |
| 交付判定 | 能在**没有真实硬件**的情况下完整演示，并且能讲清 8 种异常场景怎么处理 |

### 为什么"手写 Modbus"比"用库"值钱

工业软件面试几乎必问：帧结构长什么样、CRC 怎么算、超时怎么处理、异常码怎么解析、为什么采集要独立线程。
你用库做，只能答"调了 `modbus_read_registers`"；你手写，就能画出帧、背出多项式、讲清重试与去抖。**这 26 小时买的就是这个差别。**

### 2.2 开工前必须翻的 5 个东西

1. **Modbus 应用协议规范**（`Modbus_Application_Protocol_V1_1b3.pdf`）——只读第 6 章（功能码 3/4 与异常响应），别通读。
2. **Qt 官方 SerialPort 示例**（`terminal` / `blockingmaster`）——看它怎么处理 `readyRead` 与错误。
3. **一份开源 Modbus 实现的源码**（`libmodbus` 的 `modbus.c` 里 CRC 与帧组装部分，只看不抄）——验证你对字节序和 CRC 顺序的理解。
4. **`QSerialPort` 的线程限制说明**——一句话：`QSerialPort` 是 `QObject`，必须在**创建它的线程**里用。
5. **Modbus 异常码表**（01 非法功能 / 02 非法数据地址 / 03 非法数据值 / 04 从站设备故障）——背下来，面试会问。

### 3.3 部署（打包给别人看的时候会踩）

`windeployqt app.exe` 通常会带上 `Qt6SerialPort.dll` 和 `plugins/sqldrivers/qsqlite.dll`。
**必须人工确认**：`plugins/sqldrivers/qsqlite.dll` 存在，否则程序在自己机器上跑得好好的，拷到别人电脑一打开就报 `QSqlDatabase: QSQLITE driver not loaded`。

### 3.4 常见坑（提前知道能省半天）

| 坑 | 现象 | 原因与解法 |
|---|---|---|
| 串口被占用 | `QSerialPort::open` 返回 `PermissionError` | 同一个 COM 口只能被一个进程打开。关掉 SSCOM / Modbus Poll / 另一个实例 |
| 波特率或校验位不匹配 | 全是 CRC 错、全是乱码 | 两端必须完全一致（9600-8-N-1 是最常见组合） |
| 半双工发送未完成 | 偶尔收到自己的回显、偶发 CRC 错 | RS485 是半双工，发完要 `waitForBytesWritten()` 再切接收 |
| `QSerialPort` 跨线程 | 崩溃 / 收不到 `readyRead` | `QSerialPort` 必须在**使用它的线程**里创建；或创建后在 `moveToThread` **之前**不要 open |
| `QSqlDatabase` 跨线程 | 警告 `QSqlDatabasePrivate::database: requested database does not belong to the calling thread` | 每个线程用独立的 connection name |
| com0com 装不上 | 设备管理器里带感叹号 | Win11 需要签名版；见 3.5 备选方案 |
| RS485 的 A/B 接反 | 主站发出去完全无响应（不是 CRC 错，是**一点回应都没有**） | 把 A/B 两根线对调再试——现场排查第一招 |

## 四、怎么模拟硬件设备（核心）

**没有真实 PLC/仪表，一样能把这个项目完整做出来，而且比有硬件测得更好**——因为真设备不会配合你造异常。

### 4.1 三层方案（按顺序上，不要跳）

| 层 | 方案 | 成本 | 真实性 | 能测什么 | 不能测什么 |
|---|---|---|---|---|---|
| **第 1 层** | com0com 虚拟串口对 + **自己写的从站模拟器** | 0 元 | 协议级真实 | 正常读写、超时、异常码、错 CRC、半包、慢响应 | 电气层（RS485 电平、干扰、接地） |
| **第 2 层** | 第三方工具（Modbus Slave / Modbus Poll / QModMaster） | 0 元（试用） | 协议级真实 | **交叉验证你的帧格式与 CRC 顺序对不对** | 同上 |
| **第 3 层**（可选） | USB 转 RS485 + 一个 Modbus 继电器/温湿度模块 | 30–80 元 | 完全真实 | 电气层、A/B 接反、终端电阻、真实设备的异常码 | — |

**做不做第 3 层**：如果你打算认真投上位机岗，建议花 50 块买一个。面试时能说"我接过真实的 Modbus 仪表"和"我用虚拟串口测的"，分量完全不同。但这不影响项目交付——第 1、2 层就够验收了。

### 4.2 第 1 层：造一对虚拟串口

**方案 A：com0com（推荐）**

1. 装 com0com（Win11 用签名版），打开 `Setup` 命令行
2. 建一对端口，例如 `COM9 <-> COM10`
3. 你的主站打开 `COM9`，模拟器打开 `COM10`，两边就通了

```text
# com0com 的命令行工具（在安装目录下）
setupc.exe install PortName=COM9 PortName=COM10
list                      # 确认这对端口存在
```

**方案 B：com0com 装不上时**

- 用 **VSPD**（Virtual Serial Port Driver，商业软件，有试用期），图形界面建对
- 或者 **两块 USB 转 TTL 模块**：把模块 1 的 TX 接模块 2 的 RX、RX 接 TX、GND 对接，插在电脑上就是一对真实串口。**这个方案最稳，且不受驱动签名限制**

### 4.3 自己写从站模拟器（这一步不能省）

**为什么必须自己写：**

1. 真设备改不了行为——你不能让一台温湿度计"这次超时"、"这次返回错误码"
2. 你需要**可重复的异常注入**来验证主站的错误处理，这是面试最容易被追问的地方
3. 写从站的过程会逼你把帧格式搞对（写两遍比读十遍有用）
4. 面试时说"我自己写了从站模拟器来测主站的异常分支"——这句话的分量很重

下面是一个可以直接跑的版本（Python + pyserial，约 100 行）：

```python
#!/usr/bin/env python3
# slave_sim.py  —— Modbus RTU 从站模拟器（仅用于开发测试）
# 用法：python slave_sim.py --port COM10 --baud 9600 --slave 1 --regs 8
import argparse, math, random, time
import serial  # pip install pyserial


def crc16(data: bytes) -> int:
    crc = 0xFFFF
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = (crc >> 1) ^ 0xA001 if crc & 1 else crc >> 1
    return crc


def with_crc(body: bytes) -> bytes:
    c = crc16(body)
    return body + bytes((c & 0xFF, (c >> 8) & 0xFF))   # 低字节在前


def reg_value(addr: int, t: float) -> int:
    """造 4 种有意义的信号，方便在曲线上一眼看出区别"""
    return {
        0: int(500 + 300 * math.sin(t)),      # 正弦，会波动
        1: int(t * 10) % 1000,                # 锯齿，单调增
        2: random.randint(0, 100),            # 随机噪声
        3: 1234,                              # 常量，用来验证缩放系数
    }.get(addr, 0) & 0xFFFF


def main() -> None:
    ap = argparse.ArgumentParser()
    ap.add_argument("--port", required=True)
    ap.add_argument("--baud", type=int, default=9600)
    ap.add_argument("--slave", type=int, default=1)
    ap.add_argument("--regs", type=int, default=8)
    ap.add_argument("--timeout-rate", type=float, default=0.0, help="不响应的概率 0~1")
    ap.add_argument("--exc-rate", type=float, default=0.0, help="返回异常码的概率 0~1")
    ap.add_argument("--bad-crc-rate", type=float, default=0.0, help="返回错误 CRC 的概率")
    ap.add_argument("--slow-ms", type=int, default=0, help="延迟响应毫秒数")
    ap.add_argument("--split", action="store_true", help="把响应拆成两半发（造半包）")
    a = ap.parse_args()

    ser = serial.Serial(a.port, a.baud, timeout=0.05)
    print(f"[sim] {a.port} @ {a.baud} 8N1, slave={a.slave}, regs={a.regs}")
    t0 = time.time()
    buf = bytearray()

    while True:
        buf += ser.read(256)
        if len(buf) < 8:
            continue

        # 0x03/0x04 的请求恰好 8 字节，按此分帧（测试用足够）
        req, buf = bytes(buf[:8]), buf[8:]

        if crc16(req[:6]) != (req[6] | (req[7] << 8)):
            print("[sim] request CRC error, ignored")
            continue
        if req[0] != a.slave:
            print(f"[sim] not for me, addr={req[0]}")
            continue

        func = req[1]
        start = (req[2] << 8) | req[3]
        count = (req[4] << 8) | req[5]

        # --- 异常注入 ---
        if random.random() < a.timeout_rate:
            print("[sim] inject: NO RESPONSE (timeout)")
            continue
        if a.slow_ms:
            time.sleep(a.slow_ms / 1000.0)

        # --- 正常/异常响应 ---
        if func not in (0x03, 0x04):
            resp = with_crc(bytes((a.slave, func | 0x80, 0x01)))       # 非法功能
        elif count < 1 or count > 125:
            resp = with_crc(bytes((a.slave, func | 0x80, 0x03)))       # 非法数据值
        elif start + count > a.regs:
            resp = with_crc(bytes((a.slave, func | 0x80, 0x02)))       # 非法数据地址
        elif random.random() < a.exc_rate:
            code = random.choice((0x01, 0x02, 0x03, 0x04))
            print(f"[sim] inject: exception 0x{code:02X}")
            resp = with_crc(bytes((a.slave, func | 0x80, code)))
        else:
            t = time.time() - t0
            payload = bytes((count * 2,))                              # 字节数
            for i in range(count):
                v = reg_value(start + i, t)
                payload += bytes((v >> 8, v & 0xFF))                   # 大端
            resp = with_crc(bytes((a.slave, func)) + payload)
            print(f"[sim] func=0x{func:02X} start={start} count={count} -> OK")

        if random.random() < a.bad_crc_rate:
            resp = resp[:-2] + b"\x00\x00"                             # 错误的 CRC
            print("[sim] inject: BAD CRC")

        if a.split:
            half = len(resp) // 2
            ser.write(resp[:half]); ser.flush()
            time.sleep(0.02)
            ser.write(resp[half:])
            print("[sim] inject: SPLIT (half packet)")
        else:
            ser.write(resp)
        ser.flush()


if __name__ == "__main__":
    main()
```

**常用启动命令：**

```bash
# 1) 正常从站，4 路信号
python slave_sim.py --port COM10 --slave 1 --regs 8

# 2) 20% 概率不响应（测超时重试）
python slave_sim.py --port COM10 --timeout-rate 0.2

# 3) 每 5 帧返回一次异常码（测异常码解析）
python slave_sim.py --port COM10 --exc-rate 0.2

# 4) 响应延迟 800ms（测你的超时阈值设置是否合理）
python slave_sim.py --port COM10 --slow-ms 800

# 5) 半包（测你的接收缓冲是否会拼帧）
python slave_sim.py --port COM10 --split
```

### 4.4 第 2 层：第三方工具交叉验证（**这一步最容易被跳过，也最容易救你**）

**必须先理解一个陷阱**：你自己写的主站 + 你自己写的从站，可能对同一个地方**一致地理解错**。

举三个真实例子：

- CRC 两个字节的**高低顺序**都写反了 → 两边自测全绿，接真设备一条也读不出来
- 寄存器字节序都用小端 → 两边一致，接真设备数值全是乱码
- 帧尾都多算了一个字节 → 两边一致

**所以必须用第三方实现交叉验证**：

| 验证方式 | 怎么做 | 能证明什么 |
|---|---|---|
| 用 **Modbus Poll**（第三方主站）去读**你的从站模拟器** | 起模拟器，Modbus Poll 连 COM10（主站侧连 COM9 的话要对调） | 你的从站帧格式是对的 → 你的主站也是对的 |
| 用 **Modbus Slave**（第三方从站）去喂**你的主站** | 起 Modbus Slave 在 COM10，你的程序连 COM9 | 你能解析**别人实现的**合法帧，而不是只认自己发的 |
| 用 **QModMaster**（开源主站）同样跑一遍 | 同上 | 再多一个参考实现 |

每改一次帧组装代码，都跑一遍这两向交叉验证。**10 分钟的验证能省掉 3 小时的"为什么读不出来"。**

### 4.5 第 3 层（可选）：接真实硬件

要买的东西（总价 50 元以内可搞定）：

| 件 | 说明 |
|---|---|
| USB 转 RS485 转换器 | 注意看芯片：CH340 / CP2102 / FT232 都行，装对应驱动 |
| 一个 Modbus 从站小设备 | 继电器模块（能读能写，测写寄存器）、温湿度传感器（只能读，测 0x04）、或一个便宜的 PLC |
| 杜邦线 / 双绞线 | RS485 用双绞线，A 接 A、B 接 B、GND 对接 |

接线三条铁律：

1. **A 接 A、B 接 B**。如果完全没响应（不是 CRC 错，是彻底没动静），第一件事就是把 A/B 对调
2. **共地**：转换器的 GND 和设备的 GND 要接在一起，否则通信不稳
3. **长距离时**在总线末端加 120Ω 终端电阻（桌面上 1 米以内不用管）

### 4.6 必须先造出来的 8 种异常场景

这是这个项目的验收核心：**每一种你都要能演示"我的程序会怎么处理"**。

| # | 场景 | 怎么造 | 你的程序应该表现 |
|---|---|---|---|
| 1 | 正常响应 | 直接跑模拟器 | 曲线滚动，数值正确 |
| 2 | 从站不响应（超时） | `--timeout-rate 1.0` | 3 次重试后标记该点"采集失败"，**不卡 UI**，状态栏提示 |
| 3 | 非法数据地址 | 配置里把起始地址设到 `--regs` 之外 | 收到异常码 0x02，提示"地址越界"，不崩、不刷屏 |
| 4 | 非法功能码 | 用 SSCOM 手动发 `01 05 ...`（0x05 不在支持列表） | 收到 0x01，提示"该设备不支持此功能" |
| 5 | 从站故障 | `--exc-rate 1.0` | 收到 0x04，状态标记故障，降频重试（而不是死循环打满 CPU） |
| 6 | 响应 CRC 错 | `--bad-crc-rate 1.0` | 丢弃该帧 + 计错，不能把错数据画到曲线上 |
| 7 | 半包 / 粘包 | `--split`；或用 SSCOM 连发两帧 | 接收缓冲按长度拼帧，不丢帧、不错位 |
| 8 | 慢响应 | `--slow-ms 800` 且主站超时设 500ms | 判定超时并重试；把超时阈值调到 1200ms 后恢复正常——**这一组对比最能讲** |

> 第 8 条建议你在 README 里放一张"超时阈值 vs 丢点率"的小表（500/800/1200/2000 ms 各跑 100 次），面试时能直接证明你调过参。

## 五、功能需求

| 编号 | 需求 | 具体行为 / 验收点 |
|---|---|---|
| F1 | 串口管理 | `QSerialPortInfo` 枚举可用端口并刷新；打开/关闭；可配波特率 / 数据位 / 停止位 / 校验位；配置存 `QSettings` |
| F2 | Modbus RTU 主站（手写） | 支持 `0x03` 读保持寄存器、`0x04` 读输入寄存器。帧 = 从站地址(1) + 功能码(1) + 起始地址(2 大端) + 寄存器数(2 大端) + CRC16(2 低字节在前) |
| F3 | 超时与重试 | 响应超时可配（100–2000 ms），单点重试 3 次后标记失败；整轮采集不因单点失败而中断 |
| F4 | 异常解析 | 功能码最高位置 1 视为异常；把 01/02/03/04 翻译成中文提示；异常计入统计（异常次数 / 总请求数） |
| F5 | 轮询采集 | 周期可配 100 ms–5 s；**采集在独立线程**，UI 卡顿不影响节拍；每次记录请求时刻与响应耗时（RTT） |
| F6 | 通道配置 | 从站地址 + 寄存器表（名称 / 地址 / 类型 / 单位 / 缩放系数 / 上下限），存 JSON，支持导入导出；**配置非法要报错不能崩** |
| F7 | 实时曲线 | `QPainter` 自绘多通道折线（不用 Qt Charts）：滚动窗口、Y 轴自适应、暂停/继续、悬停显示数值、2000 点时拖动不卡 |
| F8 | 数据落库 | SQLite：`(device_id, reg_addr, value, ts)` + 时间索引；支持按时间段查询显示；支持导出 CSV |
| F9 | 阈值报警 | 每通道配上下限；超限曲线变红 + 状态栏告警 + 报警记录表；**连续 2 次超限才报**（去抖） |
| F10 | 连接状态 | 正常 / 串口断开 / 从站无响应 / 配置错误 四态可见；断开后每 2 s 自动重连，最多 10 次 |

## 八、面试追问预案

| 追问 | 你要能答出 |
|---|---|
| Modbus RTU 一帧长什么样 | 地址 + 功能码 + 数据 + CRC16（低字节在前）；能直接画在纸上；3.5 字符间隔判帧，1.5 字符为帧内间隔 |
| CRC16 怎么算 | 多项式 0xA001 反射算法，初值 0xFFFF，结果低字节先发；可以口述循环逻辑，也可以说"我用查表法优化过" |
| 为什么采集要独立线程 | 串口读写阻塞，100 ms 周期下主线程一卡就丢拍；采集线程 + 有界队列 + UI 只取最新值（这条和音视频项目共用一套说法） |
| 超时和重试怎么设计才不会堆积 | 单点重试 3 次 + 整轮跳过；用状态机而非 `sleep` 阻塞 UI；连续超时降频（周期拉长）而不是死磕 |
| 异常码怎么处理 | 功能码置 1 位 + 异常码；01/02/03/04 分别对应功能不支持/地址非法/数据非法/从站故障；异常率超阈值就报警并降频 |
| 半包粘包怎么解决 | 按功能码推算期望长度（0x03/0x04 的响应长度 = 3 + 2×数量 + 2），缓冲不足就等下次 `readyRead` |
| 曲线怎么画才不卡 | 只画可视区的点、点数固定窗口滚动丢弃、`paintEvent` 内不做数据计算、必要时 `update(rect)` 局部刷新 |
| 数据量大了怎么办 | 时间索引 + 定期归档；写入用事务批量提交（100 条一提交）；查询限制时间范围 |
| 你怎么测的（没有真设备） | **这题是送分题**：虚拟串口对 + 自写从站模拟器做异常注入 + 第三方工具交叉验证 + （可选）真实 RS485 模块 |
