## 一、怎么用这份文档

1. **D12 开工前**：把第三节（菜单栏）通读一遍，删掉你不想做的项，剩下的就是你的功能边界
2. **每天开工**：按第十节的"工时平衡"看今天该做哪几项，不要按界面区域做，按优先级做
3. **D16 交付前**：用第十二节的验收清单逐条点一遍
4. **面试前**：把 3.8 的"菜单与状态联动矩阵"背下来——它能证明你想过状态机，而不是只堆控件

## 三、菜单栏（重点）

### 3.1 四条设计原则

| 原则 | 说明 |
|---|---|
| **① 每一项目都必须有实现** | 不做灰色占位项。面试官真的会点菜单，点到一个没反应的项比没有这个菜单更糟 |
| **② 一个动作一个 QAction 对象** | 菜单项、工具栏按钮、左栏按钮共用**同一个 `QAction*`**。否则会出现"菜单里能点、工具栏是灰的"这种 bug，而且启用状态要维护两遍 |
| **③ 快捷键必须查冲突** | Qt 里两个 QAction 抢同一个快捷键时，**其中一个会静默失效**，不报错。3.9 给了全表，写完照着验一遍 |
| **④ 危险操作二次确认** | 清空数据、删除通道、未保存退出——三个地方必须弹确认框 |

### 3.8 菜单与状态的联动矩阵

这是整套菜单最容易被忽略、也最能体现工程思维的一块。**同样的菜单项，在不同状态下必须变灰或变可用。**

状态定义：

| 状态 | 含义 |
|---|---|
| **S1 未连接** | 串口没打开 |
| **S2 已连接·空闲** | 串口开着，没在采集 |
| **S3 采集中** | 正在按周期轮询 |
| **S4 已暂停** | 串口占着，不下发请求 |
| **S5 故障** | 串口掉线 / 连续超时超阈值 |

| 动作 \ 状态 | S1 | S2 | S3 | S4 | S5 |
|---|---|---|---|---|---|
| 打开工程 (F-02) | ✓ | ✓ | ✗ | ✓ | ✓ |
| 保存工程 (F-03) | ✓ | ✓ | ✓ | ✓ | ✓ |
| 导出数据 (F-07) | ✗ | ✓ | ✓ | ✓ | ✓ |
| 连接 (D-02) | ✓ | ✗ | ✗ | ✗ | ✓ |
| 断开 (D-03) | ✗ | ✓ | ✓ | ✓ | ✓ |
| 开始采集 (D-04) | ✗ | ✓ | ✗ | ✓ | ✗ |
| 暂停 (D-05) | ✗ | ✗ | ✓ | ✗ | ✗ |
| 停止 (D-06) | ✗ | ✗ | ✓ | ✓ | ✗ |
| 单次读取 (D-07) | ✗ | ✓ | ✗ | ✓ | ✗ |
| 新增/删除通道 (E-01/E-03) | ✓ | ✓ | **✗** | ✓ | ✓ |
| 清空数据 (E-07) | ✓ | ✓ | **✗** | ✓ | ✓ |
| 通信设置 (D-10) | ✓ | ✓ | **✗** | ✓ | ✓ |
| 曲线设置 (V-06) | ✓ | ✓ | ✓ | ✓ | ✓ |

实现方式：一个 `updateActionStates()` 函数，状态变化时统一调一次，**不要在每个槽函数里零散地 setEnabled**。这条写进 `docs/decisions.md`。

## 五、左栏

### 5.1 串口设置

| 编号 | 控件 | 行为 / 细节 |
|---|---|---|
| SP-01 | 端口下拉 | 枚举 + 设备描述；打开串口时该下拉**置灰**（运行中不能换口） |
| SP-02 | 波特率下拉 | 标准 6 档；非标准值允许手输 |
| SP-03 | 帧格式 | 合并「数据位·校验·停止位」为一个下拉，比三个下拉更省空间且不易配错 |
| SP-04 | 提示行 | 当前帧格式的完整解释（8 数据位 · 无校验 · 1 停止位），灰色小字 |
| SP-05 | 超时 | 100–2000 ms，影响单帧等待 |
| SP-06 | 重试 | 0–5 次；重试后仍失败则标记该点失败并计数 |

### 5.2 Modbus 设置

| 编号 | 控件 | 行为 / 细节 |
|---|---|---|
| MB-01 | 功能码 | 03 读保持寄存器 / 04 读输入寄存器（这两项足够，别的别加） |
| MB-02 | 起始地址 | 十六进制输入，校验 0x0000–0xFFFF |
| MB-03 | 数量 | 1–125（协议上限）；与起始地址联动校验越界 |
| MB-04 | 从站地址 | 采集中置灰 |

### 7.3 数据存储（3 h，含 SQLite）

| 编号 | 元素 | 行为 / 细节 |
|---|---|---|
| DB-01 | 库文件与体积 | `hmi.db · 3.2 MB`，体积用 `QFileInfo` 实时算 |
| DB-02 | 记录数 | `SELECT COUNT(*)`，启动时查一次，写入时自增 |
| DB-03 | 时间范围下拉 | 最近 1 小时 / 24 小时 / 自定义 |
| DB-04 | 查询 / 导出 | 查询走 T-01 的同一套 SQL，导出走 F-07 |

**建表（照抄）**：

```sql
CREATE TABLE IF NOT EXISTS t_sample (
  id       INTEGER PRIMARY KEY AUTOINCREMENT,
  reg_addr INTEGER NOT NULL,
  raw      INTEGER NOT NULL,
  value    REAL    NOT NULL,
  ts       INTEGER NOT NULL          -- Unix 毫秒
);
CREATE INDEX IF NOT EXISTS idx_sample_ts ON t_sample(reg_addr, ts);
```

写入要点：**攒 50 条一个事务**批量 `execBatch`，别一条一个事务（1 小时 7200 条会写崩性能）。

## 十一、空态 / 错误态 / 边界清单

这部分决定"像不像一个工程软件"，也是最容易被面试官点出来的地方。

| 场景 | 应该的表现 |
|---|---|
| 没插串口 / 一个端口都没有 | 端口下拉显示「未检测到串口」，连接按钮置灰，状态栏给提示，**不弹错误框** |
| 端口被别的程序占用 | 弹框：「COM9 被占用（可能被串口助手打开），请关闭后重试」——**说清原因和解法** |
| 未连接时点"开始采集" | 按钮本身就是灰的（状态联动）；万一触发了，状态栏提示而非弹框 |
| 采集中拔掉 USB | 统计里超时+1、状态栏变"断开"、自动重连 3 次；**UI 不能卡** |
| 从站返回异常码 0x02 | 该点状态显示"地址非法"，报警列表记一条故障，**曲线不画断点**（用断线连接或留空） |
| 收到 CRC 错误的帧 | 丢弃 + 计数，**不能把错数据画到曲线上**（这是最容易出的事故） |
| 半包（帧被拆两次） | 接收缓冲按期望长度拼帧，不足则等下次 `readyRead` |
| 通道全不勾选 | 曲线区显示「未选择通道」空态文案，不画空白网格 |
| 查询结果为空 | 表格显示「该时间段无数据，试试扩大范围」，不显示 0 行表格 |
| 工程 JSON 字段缺失 | 加载失败并指出字段：「第 3 个通道缺少 field: unit」；**不能整份丢弃** |
| 缩放系数为 0 | 校验拦截：「缩放系数不能为 0（会导致工程值恒为 0）」 |
| 数据库写满 / 权限不足 | 停止落库但**继续采集与显示**，状态栏红字提示「落库已停止」——采集不能因为存不进去而停 |
